# Calibrating the robot

The robot measures its own drive constants. One web page on the robot runs every measurement step, shows each value with where it came from, and saves results on the Control Hub the moment a step finishes. This replaces Pedro Pathing's AutoTune page and also measures what PathMaker needs.

## Opening the page

1. Deploy the app, connect the laptop to the robot's Wi-Fi, and open **http://192.168.43.1:8090**. The page is there whenever the robot app runs.
2. On the Driver Hub, choose **Calibrate** (TeleOp, group "calibration"), press INIT, then ▶. Steps run only while this OpMode runs.
3. Click **Run** on a step and follow the prompts. Before anything moves, the page waits for you to press **Start**. **Stop on the Driver Hub ends any step at once**; **Abort** on the page does the same.

You can close the page, reload it or open it on a second laptop at any time. Everything lives on the robot.

## The steps, in order

| # | Step | What happens | Space |
|---|---|---|---|
| 1 | Motor directions | Each wheel spins in turn; you say which way it turned | On blocks or on the floor |
| 2 | Odometry ports and directions | You push the robot one tile forward, then one tile to its left. Finds which OctoQuad port each pod is on and which way it counts. **Catches swapped pod cables** | 2 tiles, nothing powered |
| 3 | OctoQuad heading and offsets | You turn the robot by hand exactly 10 times, then push it; the robot then spins in place to find the pod offsets. **Run it twice**: the heading scale is marked "measured once" until two runs agree within 0.5 % | 1 tile around the robot |
| 4 | Pedro Foresight | 12 powered runs: top speed, coasting, braking, heading and position gains | About 8 ft ahead and to the left |
| 5 | PathMaker drive | Speed noise standing still; start-up power (kS) forward, sideways and turning; braking from speed with the motors braking | About 4 ft; every run stops at the distance limit you enter |
| 6 | Pedro tests | Hold, line and curve tests to check the result | As for step 4 |

Run them in this order the first time; later you can rerun any single step. Step 2 tells you if the ports changed. Step 3 must then be run again, because the offsets depend on the ports.

## Where values come from

Every value has three layers, and the first one that exists is used:

1. **Measured**: saved on the Control Hub in `/sdcard/FIRST/settings/calibration.json`. It survives app restarts and redeploys, and keeps the last 5 measurements of each value.
2. **Committed**: `TeamCode/.../calibration/RobotCalibration.java`, in git.
3. **Default**: in `CalibrationKeys.java`. Defaults are safe, not good. Pedro's gains default to zero, so Pedro cannot follow a path or hold a position until step 4 has run; the bay-b bot's Drive test then drives by hand only.

The **All values** table shows all three layers for every value. Use **Edit** to type a value in (it counts as measured) and **Revert** to forget the measured value.

## Keeping the values in git

The file on the Control Hub belongs to that one robot. After a calibration session:

1. Click **Export Java**. It downloads `RobotCalibration.java`, containing every measured and committed value with the date it was measured.
2. Replace `TeamCode/src/main/java/org/firstinspires/ftc/teamcode/calibration/RobotCalibration.java` with it and commit.

**Download file** saves `calibration.json` itself, as a backup.

## For programmers

| File | Job |
|---|---|
| `calibration/Calibration.java` | The three layers, saving and loading the file, export |
| `calibration/CalibrationKeys.java` | Every value: id, group, label, unit, default |
| `calibration/RobotCalibration.java` | Committed values (generated by Export Java) |
| `calibration/CalibrationServer.java` | The web server (port 8090), started with the robot app via `@OnCreateEventLoop` |
| `calibration/CalibrateOpMode.java` | Runs the step the page asks for, on the OpMode thread |
| `calibration/runner/*` | The step runner. `Procedure` and `TuningOpMode` have the same calls as Pedro AutoTune's classes, so Pedro's procedures run unchanged |
| `calibration/steps/*` | The steps. Mecanum, OctoQuad, Foresight and Tests come from the Pedro Quickstart (BSD 3-Clause); AxesCheck and DriveCharacterization are ours |
| `assets/calibration/index.html` | The page: plain HTML and JavaScript with no outside files, because the robot's Wi-Fi has no internet |
| `pedro/Constants.java` | Builds Pedro's configuration from the calibration on every call |

A step reports a result with `result("name", value)`. If `"<step id>.name"` (or `name` itself) is a key in `CalibrationKeys`, the value is saved; otherwise it is only shown. To add a value, define it in `CalibrationKeys`, then read it with `Calibration.getDouble("id")` and the other getters.

Safety rules for new powered steps: wait for `waitForStart()` before powering anything; check `isStopRequested()` in every loop; stop at a distance limit and a time limit. The runner sets every motor's power to zero after each run, and whenever a step ends or fails.
